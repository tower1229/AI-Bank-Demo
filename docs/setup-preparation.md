# Setup Preparation Checklist

This checklist prepares Cloudflare, Telegram, and OpenClaw for the AI Bank Demo.

Some commands can be run now. Commands that depend on the Worker code are marked as "after implementation".

## 0. Things to Prepare

Required accounts and access:

- A Cloudflare account.
- A Telegram account that can talk to `@BotFather`.
- SSH or terminal access to the cloud server where OpenClaw is running.
- Access to the OpenClaw config file on that server.

Secrets to create and store in a password manager:

- `TELEGRAM_BOT_TOKEN`: generated by BotFather.

Do not commit real tokens to git.

## 1. Create the Telegram Bot

In Telegram:

1. Open `@BotFather`. Confirm the handle is exactly `@BotFather`.
2. Send `/newbot`.
3. Use a display name such as:

   ```text
   AI Bank Demo
   ```

4. Choose a username ending in `bot`, for example:

   ```text
   ai_bank_demo_bot
   ```

5. Copy the token BotFather returns. Save it as `TELEGRAM_BOT_TOKEN`.

Recommended profile setup in BotFather:

1. Send `/setdescription`.
2. Select the new bot.
3. Use:

   ```text
   Demo assistant for operating a simulated private banking system through OpenClaw.
   ```

4. Send `/setabouttext`.
5. Use:

   ```text
   AI Bank Demo assistant.
   ```

Do not configure a Telegram webhook manually. OpenClaw should own the bot directly. The v1 demo uses private DMs only.

## 2. Prepare Cloudflare Locally

From the repo root:

```bash
cd /Users/zangtao/Workspace/tower1229/AI-Bank-Demo
```

Log in to Cloudflare:

```bash
npx wrangler@latest login
npx wrangler@latest whoami
```

Create the production D1 database:

```bash
npx wrangler@latest d1 create ai-bank-demo-db
```

Save the output. The important fields are:

- `database_name`
- `database_id`

The future `wrangler.toml` should include a binding like this:

```toml
[[d1_databases]]
binding = "DB"
database_name = "ai-bank-demo-db"
database_id = "<database_id_from_wrangler>"
migrations_dir = "migrations"
```

The v1 MCP endpoint intentionally does not use a shared secret. Keep `.dev.vars` local if you add deployment-specific values later.

## 3. Prepare OpenClaw Telegram Channel

On the OpenClaw server, first check current state:

```bash
openclaw status --deep
openclaw channels list
openclaw channels status
```

Add the Telegram bot account:

```bash
openclaw channels add \
  --channel telegram \
  --account ai-bank-demo \
  --name "AI Bank Demo Bot" \
  --token "$TELEGRAM_BOT_TOKEN"
```

Configure Telegram DM access as public for this demo:

```js
{
  channels: {
    telegram: {
      enabled: true,
      dmPolicy: "open",
      allowFrom: ["*"],
      groupPolicy: "disabled"
    }
  }
}
```

If the OpenClaw config uses account-specific Telegram config, place the token and policy under the `ai-bank-demo` account according to that config shape.

Restart or reload the OpenClaw Gateway using your server's normal process manager.

Then verify:

```bash
openclaw channels list
openclaw channels status --probe
openclaw logs --follow
```

Send a DM to the bot from Telegram:

```text
hello
```

The logs should show a Telegram inbound event from your user.

## 4. Prepare the Dedicated OpenClaw Agent

Create or configure a dedicated `ai-bank` agent instead of using the default agent.

Recommended config shape:

```js
{
  agents: {
    list: [
      {
        id: "ai-bank",
        name: "AI Bank Demo",
        workspace: "~/.openclaw/workspace-ai-bank"
      }
    ]
  },
  bindings: [
    {
      agentId: "ai-bank",
      match: {
        channel: "telegram",
        accountId: "ai-bank-demo"
      }
    }
  ]
}
```

Copy this repo file into the agent workspace or system prompt source:

```text
docs/openclaw-agent-instructions.md
```

The important behavior rules are:

- Telegram can submit onboarding applications but cannot approve them.
- Transfers and product purchases require confirmation before tool use.
- All writes must pass `confirmed: true`.
- USD only.
- DM only.

## 5. Register the Bank MCP Endpoint

This step is after the Cloudflare Worker MCP endpoint is deployed.

Use the deployed URL:

```text
https://<bank-demo-domain>/mcp
```

Register it in OpenClaw:

```bash
openclaw mcp set ai-bank '{
  "url": "https://<bank-demo-domain>/mcp",
  "transport": "streamable-http",
  "connectionTimeout": 10000
}'
```

If the running OpenClaw adapter expects SSE/HTTP instead of streamable HTTP, use:

```bash
openclaw mcp set ai-bank '{
  "url": "https://<bank-demo-domain>/mcp",
  "connectionTimeout": 10000
}'
```

Check the registry:

```bash
openclaw mcp list
openclaw mcp show ai-bank --json
```

Important: `openclaw mcp set` saves the config. It does not prove the remote MCP endpoint is reachable. After implementation, run an actual tool-list or test call from the OpenClaw runtime.

## 6. Validation Checklist

Before implementation:

- Telegram bot exists.
- Token is saved securely.
- Cloudflare login works.
- D1 database exists.
- OpenClaw server can add/list the Telegram account.
- OpenClaw receives a DM from the bot.

After implementation:

- `wrangler.toml` contains the D1 binding.
- Remote D1 migrations apply successfully.
- Worker deploy succeeds.
- Web console loads.
- Seed data is visible.
- OpenClaw can list or call bank MCP tools.
- Telegram onboarding, transfer, and product purchase flows work end to end.
